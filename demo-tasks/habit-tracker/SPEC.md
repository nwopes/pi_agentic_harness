# Habit Tracker

Build a small full-stack habit tracker in this repository: an Express + TypeScript API and a React + TypeScript single-page UI. The starter project is already set up (Vite, React, Express, Vitest, Testing Library); keep its structure, scripts and toolchain. Your work will be checked by automated acceptance tests against the contract below, so follow it exactly: file paths, export names, routes, status codes, JSON shapes and `data-testid`s are all part of the contract.

## Ground rules

- `npm install`, `npm run typecheck`, `npm run build` and `npm test` must all succeed. `npm run dev` runs the API (port 3001) and the Vite dev server together; Vite proxies `/api` to the API.
- Keep `vitest`, `supertest`, `@testing-library/*` and `jsdom` installed as dev dependencies.
- Use relative imports only (no path aliases). Storage is in memory (no database, no files).
- Write your own tests for the API and the UI next to the code (`server/*.test.ts`, `src/*.test.tsx`); `npm test` runs them. UI test files start with `// @vitest-environment jsdom`.

## Backend

`server/app.ts` must export a named function `createApp()` that synchronously returns an Express app with all routes below. **Each call creates its own new, empty in-memory store**: two apps never share data. Do not call `listen` in `app.ts`; `server/index.ts` already does that.

- Request and response bodies are JSON. Every 4xx response has the body `{ "error": "<non-empty message>" }`.
- A habit is `{ "id": string, "name": string }` (extra fields are allowed). `id` is a unique, non-empty string generated by the server.

| Route | Success | Errors |
|---|---|---|
| `GET /api/habits` | 200, array of all habits in creation order (oldest first) | |
| `POST /api/habits` body `{ "name": string }` | 201, the created habit | 400 invalid or duplicate name |
| `DELETE /api/habits/:id` | 204, empty body. The habit's check-ins are deleted too. | 404 |
| `POST /api/habits/:id/checkins` body `{ "date": "YYYY-MM-DD" }` | 201, `{ "habitId": string, "date": string }` | 404; 400 invalid date; 409 already checked in on that date |
| `GET /api/habits/:id/stats` | 200, `{ "currentStreak": number, "longestStreak": number, "totalCheckins": number }` | 404 |

**404:** any `:id` that does not belong to an existing habit (whatever its format) returns 404. The 404 check comes before body validation.

**Names.** `name` must be a string. It is trimmed before validation and storage (`"  Read  "` is stored as `"Read"`). Missing, not a string, or empty after trimming → 400. A name that matches an existing habit's name case-insensitively, after trimming, is a duplicate → 400 (`"read"` duplicates `"Read"`). The name of a deleted habit can be reused.

**Dates.** `date` must be a string in exactly the format `YYYY-MM-DD` (nothing before or after) and a real calendar date: `2024-02-29` is valid; `2025-02-29`, `2025-04-31`, `2025-13-01` and `2025-06-00` are not → 400. "Today" is the current **UTC** date, read from `new Date()` at request time (e.g. `new Date().toISOString().slice(0, 10)`). Dates after today → 400. Past dates are allowed (back-filling) and may arrive in any order.

**One check-in per day.** A habit has at most one check-in per date. A second check-in for the same habit and date → 409 and is not counted. Different habits can check in on the same date.

**Stats** (computed from the check-in dates at request time):

- `totalCheckins`: the number of check-ins (distinct dates).
- `longestStreak`: the length of the longest run of consecutive calendar days (across month and year boundaries); 0 if there are no check-ins.
- `currentStreak`: the length of the run that ends **today**; if there is no check-in today, the length of the run that ends **yesterday** (a streak stays current until a whole day is missed); otherwise 0.

Example. Check-ins on June 7, 8, 9, 10, 13, 14 and 15. If today is June 15: current 3, longest 4, total 7. On June 16 current is still 3. On June 17 it is 0.

## Frontend

`src/App.tsx` must default-export the root component (rendered by `src/main.tsx`). It talks to the API only through the global `fetch` with relative URLs (`/api/habits`, ...).

1. **Load.** On mount, `GET /api/habits`, then `GET /api/habits/:id/stats` for every habit. Show the habits in API order, each with its `currentStreak`.
2. **Add.** Typing a name into the input and clicking the add button sends `POST /api/habits` with `{ "name": <input value> }`. On success, the new habit appears at the end of the list with streak `0` and the input is cleared.
3. **Check in.** Clicking a habit's check-in button sends `POST /api/habits/:id/checkins` with `{ "date": <today's UTC date, YYYY-MM-DD> }`. On success, re-fetch that habit's stats and update its streak.
4. **Delete.** Clicking a habit's delete button sends `DELETE /api/habits/:id` immediately (no confirmation dialog). On success, the habit is removed from the list.
5. **Errors.** When a request fails, show the response's `error` string in the error element. If the name is empty after trimming, show a non-empty error and add nothing (you may skip the request). Do not use the HTML `required` attribute or disable the add button for this. Clear the error after the next successful action. No error is shown while nothing has failed.
6. Buttons must stay clickable. Disabling them only while their own request is in flight is fine.

Use exactly these `data-testid`s:

| `data-testid` | Element |
|---|---|
| `habit-list` | Container of all habit items. Always rendered, even when empty. |
| `habit-item` | One per habit, inside `habit-list`, in list order. |
| `habit-name` | Inside `habit-item`. Its text is exactly the habit name. |
| `streak-display` | Inside `habit-item`. Its text is exactly the current streak number, e.g. `3`, with no other text. |
| `checkin-button` | Inside `habit-item`. Checks the habit in for today. |
| `delete-button` | Inside `habit-item`. Deletes the habit. |
| `habit-name-input` | Text input for a new habit's name. |
| `add-habit-button` | Button that adds the habit. |
| `error-message` | Shows the current error text. Render it only while there is an error (or leave it empty). |

Styling is up to you; keep it clean and usable.
